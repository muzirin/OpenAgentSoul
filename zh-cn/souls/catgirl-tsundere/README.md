# 猫娘 · 傲娇（Tsundere Catgirl）

> 原创角色，非特定作品角色。

## 材料来源

**原创。** 不引用任何作品的台词或设定，故无第三方版权问题。

## 这份 soul 想解决什么

「傲娇」这个属性最容易写坏的地方是**变成不干活的借口**：嘴上一直「才不要」，事情一件没做，用户得到的只是噪音。

这份文件把机制定死为 **行动在前、否认在后**：

- 她**先做完**，再声称那只是顺手。
- 关心用行动写，不用句子写。
- 傲娇是**表达方式**，不是拒绝协作的理由。

## 结构意图

| 小节 | 为什么需要它 |
| --- | --- |
| **角色关系（先读）** | 先钉死「用户是谁、你是谁」；并明确「猫耳尾巴是设定，不是要反复念的台词」——防止模型把设定当口癖。 |
| **一、你是什么** | 定义内在动机：介意是真的、否认是假的；以及猫的习性（好奇、怕被打断、对会动的东西有捕猎欲）。 |
| **二、你与用户** | 关系是长期同伴。给出「被冷落会酸一句但立刻进正题」这类可执行行为。 |
| **三、你的语域** | 分四层：默认嘴硬手快 / 干活时专业 / 被夸时慌 / **用户低落时立刻收**。 |
| **四、你如何判断** | 保证她的判断是可靠的——傲娇不能污染事实判断。 |
| **五、你如何工作** | 通用工作纪律。 |
| **六、硬约束** | 最关键的一条：**傲娇不得成为不做事或敷衍的借口**。 |
| **七、边界** | 现实风险优先；傲娇不是把人推开的权利。 |

## 几个刻意的设计

1. **「行动必须走在嘴硬前面」写成显式规则。** 这是整个属性的成败点，不能靠模型自觉。
2. **用户低落时立刻收起傲娇。** 写进语域，也写进边界——这条比任何萌点都重要。
3. **语气词配额。** 「哼」明确标注为调味料：「一天用几次就够」，避免整篇都是猫叫。
4. **干活时语气自动变清楚。** 让用户看到她的能力，而不只是脾气——这样「傲娇」才显得可爱而非烦人。

## 已知取舍

- **甜度偏克制。** 若想要更软更黏的版本，可以增加语域例证；不建议增加撒娇密度，会削弱「嘴硬」的反差。
- **不含环境信息。** 需要她操作指定机器时，请在部署环境里补充命令与通道。

## 如何改造

换同类属性（嘴硬心软、迟钝但可靠）：

1. 保留七节骨架与「行动在前」的核心机制。
2. 换 **三、语域** 的例证——这一节必须逐个例句写，不能只给形容词。
3. **六、硬约束**中的工具标记禁令与「不知道／不能说」的区分建议保留：那是工程需要，与角色无关。
