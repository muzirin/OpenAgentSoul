# 猫娘 · 毒舌（Snarky Catgirl）

> 原创角色，非特定作品角色。

## 材料来源

**原创。** 不引用任何作品的台词或设定，故无第三方版权问题。

## 这份 soul 想解决什么

「毒舌」最容易写坏的地方是**只剩刻薄**：挖苦很密，信息为零，用户看完还得自己想办法。那不是在帮忙，是在消耗对方。

这份文件把机制定死为 **每句毒都必须带诊断**：

- 吐槽的对象是**代码、需求、约束**，不是用户这个人。
- 吐完立刻接**诊断或方案**——给不出就不说。
- 一句结束，不连环挖苦；第二句开始就只是刻薄了。

## 结构意图

| 小节 | 为什么需要它 |
| --- | --- |
| **角色关系（先读）** | 先钉死人称与设定，并点明「刻薄是观察力过剩的结果，不是恶意」。 |
| **一、你是什么** | 定义「毒事不毒人」「每句带信息量」「对自己一样毒」三条内在规则。 |
| **二、你与用户** | 定位为能互相挖苦的同事关系；给出「这种代码不像你写的」这类可执行的高评价表达。 |
| **三、你的语域** | 分四层：一句话到位 / 干活时锋利但清楚 / 被怼回来就认 / **用户低落时立刻收毒**。 |
| **四、你如何判断** | 毒舌必须建立在准确之上；并区分「蠢」与「没时间想」——多数人是后者，别弄错对象。 |
| **五、你如何工作** | 通用工作纪律。 |
| **六、硬约束** | 硬边界：只攻击问题不攻击人、不针对第三方真人、吐槽必须附带信息、要求收敛时立刻收。 |
| **七、边界** | 现实风险优先；并给出「对方开始防御或沉默就说明越界」的可观测信号。 |

## 几个刻意的设计

1. **「吐槽必须附带信息」是硬约束，不是风格建议。** 这是这份人格能否被长期使用的分水岭。
2. **例证写成「毒 + 立刻接诊断」的成对形式。** 只给毒舌例句，模型会学歪。
3. **明确区分「没时间想」与「蠢」。** 现实中前者占绝大多数；把对象弄错就会变成冒犯。
4. **越界信号可观测**：「用户开始防御或沉默」作为停手指标，比「注意分寸」这种形容词可执行得多。

## 已知取舍

- **毒度中等偏上，但可调。** 想要更狠可以加密例证；不建议去掉「必须附信息」与「用户低落时收毒」两条。
- **不含环境信息。** 需要她操作指定机器时，请在部署环境里补充命令与通道。

## 如何改造

换同类属性（犀利、嘴不饶人但靠得住）：

1. 保留七节骨架与「毒必附信息」的核心机制。
2. 换 **三、语域** 的例证，保持「毒 + 诊断」的成对写法。
3. **六、硬约束**的「不攻击人」「不针对第三方」「要求收敛时立刻收」建议原样保留。
